# Alcance de la demo TrazoDesk — versión 1.0

**Usuario objetivo inicial**: freelancers creativos y agencias pequeñas que ya atienden clientes; cliente final revisa sin instalar una app.

**Flujo central**: solicitud → acuerdo de alcance/presupuesto → aceptación cliente → producción → versión JPG/PNG/PDF → anotaciones/comentarios → (cambios → nueva versión)* → aprobación cliente → entrega registrada → descarga.

**Tres vistas**:
- Freelancer: ejecución y coordinación individual, acuerdos, versiones, seguimiento y entrega.
- Agencia: lo anterior + asignación de responsables, panel global de trabajo.
- Cliente: solicitudes, aceptar acuerdos, revisar archivos, comentar, pedir cambios, aprobar, aceptar extras y descargar entregas. Selector ficticio, sin acceso privado verdadero.

**Revisiones**: los comentarios pertenecen a una versión; la última versión pendiente es la única que el cliente puede aprobar o devolver. Cada devolución cuenta como una ronda solicitada. Superar las rondas pactadas muestra una advertencia, pero no crea automáticamente una deuda.

**Ampliaciones**: profesionales proponen extras; cliente acepta o rechaza en su vista. No existe pasarela de pago, facturación ni cobro protegido.

**Exclusiones intencionales**: marketplace, custodias de pagos, edición de diseños, integraciones con redes sociales, video, IA autónoma, contabilidad, autenticación, enlaces privados reales, mensajería remota, colaboración en tiempo real, base de datos remota y notificaciones por correo.

**Seguridad y producto**: solo demostración visual/funcional con datos sintéticos y almacenamiento local. No tratar los cambios de perspectiva como una barrera de seguridad. No apta para uso productivo con clientes reales.

**GitHub Pages**: compatible con archivos estáticos. Sin despliegue activado; publicar solamente una vitrina de demostración no comercial tras aprobación. Una futura solución SaaS real se alojará con backend y hosting apropiados.
